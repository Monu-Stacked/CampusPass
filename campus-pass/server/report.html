Project Overview

CampusPass is a high-performance, full-stack web-based event ticketing and digital attendance ecosystem designed specifically for higher educational institutions like NIT Raipur. It addresses the recurring challenges associated with organizing technical workshops, cultural fests, hackathons, sports tournaments, and academic symposiums.

Problem Addressed

Traditional event management in colleges relies heavily on manual sign-in sheets, paper tickets, or unstructured Google Forms. These mechanisms suffer from severe systemic deficiencies:

  • Lack of Real-Time Concurrency Protection: Static forms cannot enforce strict capacity ceilings, leading to severe auditorium overbooking when hundreds of students submit entries simultaneously.
  • Ticket Forgery and Pass Sharing: Static confirmation emails or screenshots can easily be forwarded, shared, or printed multiple times, allowing unauthorized gate entry and crowding.
  • Inefficient Entry Check-In: Searching through long alphabetic printouts at the auditorium entrance creates severe bottlenecks, delayed event commencement, and poor user satisfaction.
  • Inaccurate Attendance Logging: Manual marks on paper sheets are prone to human error, loss of physical documents, and cumbersome post-event compilation.

Project Objectives

  • Centralized Event Directory: Provide a clean portal displaying upcoming campus events, venue coordinates, schedule, and live seat vacancy counters.
  • Atomic Concurrency-Controlled Registration: Implement database transactions to guarantee that zero overbooking occurs, even under concurrent high-volume traffic bursts.
  • Cryptographic Digital Pass Issuance: Generate high-density QR code passes bound to high-entropy 256-bit random tokens, stored securely as SHA-256 hashes.
  • Rapid Multi-Channel Check-In: Equip event coordinators with an integrated mobile camera scanner and fallback manual code entry for rapid check-ins.
  • Duplicate Entry Prevention: Utilize atomic database query locks to ensure a pass can be checked in exactly once, immediately flagging repeat scans with timestamps.
  • Automated Attendance Auditing: Provide organizers with instant CSV attendance export capability containing complete attendee metadata and ISO check-in times.

Project Scope

The system delivers a production-grade prototype featuring JWT organizer authentication, event CRUD operations, student registration, downloadable HTML5 canvas passes, automated WebRTC camera scanning, and real-time dashboard analytics.

Abstract

In educational institutions, coordinating extracurricular activities, tech symposiums, and departmental conferences necessitates an automated, secure, and friction-free ticketing and attendance infrastructure. CampusPass is an end-to-end full-stack web application developed using the MERN stack (MongoDB, Express.js, React.js, Node.js) and Vite that modernizes campus event access control.

The architecture is split into two synchronized interfaces: a public student portal for event discovery and instant pass reservation, and an authenticated administrative dashboard for event organizers. When a student registers, the system initiates a MongoDB multi-document ACID transaction with session locking. The transaction verifies whether the current booked seats count is strictly less than the maximum hall capacity, atomically increments the seat count, and generates a unique ticket document. This guarantees strict concurrency safety and completely prevents overbooking under high-concurrency registration spikes.

To prevent pass forgery and screenshot duplication, CampusPass implements a zero-trust cryptographic token model. For each ticket, a 256-bit cryptographically secure pseudorandom token is generated on the server. The database stores exclusively the irreversible SHA-256 digest of this token, while the raw token is encoded into a high-density QR code presented to the student. During gate entry, the organizer scans the QR code via an integrated camera scanner. The backend computes the hash of the scanned token and executes an atomic findOneAndUpdate query with the guard isCheckedIn: false. This guarantees that duplicate scans or screenshot sharing are immediately caught and flagged with the exact previous check-in timestamp.

The client application leverages React 18, Vite ESM packaging, and html2canvas for client-side rasterization of event passes into downloadable PNG images. Comprehensive testing confirmed 100% test case pass rates across registration validation, capacity constraints, atomic check-ins, duplicate scan rejections, and CSV attendance generation.

Keywords: Event Ticketing, QR Code Authentication, Concurrency Control, MongoDB ACID Transactions, MERN Stack, Atomic Updates, Digital Attendance.

Introduction

Universities and institutes host numerous academic, technical, cultural, and sports gatherings throughout the academic calendar. At an premier institute like the National Institute of Technology Raipur, student clubs and departments frequently organize workshops, coding competitions, robotics challenges, and guest lectures.

A successful event relies heavily on seamless entry management. When thousands of students seek entry into an auditorium with 500 seats, traditional manual lists lead to chaotic crowds, gate disputes, and compromised safety.

Key Architectural Modules

CampusPass resolves these operational challenges through five tightly integrated functional modules:

  • Organizer Authentication & Event Management: Provides secure administrative sign-in powered by Bcrypt hashing and JSON Web Tokens (JWT). Organizers can schedule events, set venue parameters, and define strict seat quotas.
  • Student Event Discovery & Registration: A clean, responsive user interface displaying active campus events, schedules, venue details, and real-time seat availability counters.
  • Cryptographic Digital Pass Engine: Generates unique, tamper-proof event passes containing student credentials, a six-character hexadecimal fallback code, and a high-density QR code rendered directly in the browser.
  • Gatekeeper Check-In & Verification Engine: An integrated scanner utilizing the device camera via WebRTC (html5-qrcode) and an alternative manual ticket code submission input, enabling check-in times under 1.5 seconds per attendee.
  • Live Dashboard & Attendance Auditing: Visual progress indicators displaying percentage capacity booked, current check-in tallies, and one-click RFC 4180-compliant CSV attendance export.

User Roles & Access Control

  • Student / Attendee (Public Role): Can view public events, inspect remaining seats, register with college credentials, and download event passes.
  • Event Organizer (Authorized Role): Accesses protected routes via bearer tokens to manage events, execute admission scans, and download attendance rosters.

Technology Stack

The CampusPass platform is architected entirely using modern JavaScript/ECMAScript standards across both client and server tiers, maximizing modularity, developer ergonomics, and runtime efficiency.

Frontend Technologies

  • React 18.3: Powers the single-page application (SPA) using declarative component architecture, virtual DOM reconciliation, and functional state hooks (useState, useEffect, useRef).
  • Vite 6: Modern build tool and development server utilizing native ES Modules (ESM) for instantaneous Hot Module Replacement (HMR) and optimized Rollup production bundling.
  • React Router DOM 6.28: Handles client-side routing, URL parameter extraction, and programmatic navigation between event discovery, registration, and organizer portals.
  • html2canvas 1.4: High-fidelity rasterization library that reads the DOM tree of the student pass component and renders it into a high-resolution PNG image on the client machine.
  • html5-qrcode 2.3: Cross-platform barcode and QR code scanning library operating directly over WebRTC video streams on desktop and mobile web browsers.

Backend Technologies

  • Node.js (v24): High-throughput, non-blocking asynchronous JavaScript runtime handling concurrent I/O operations effortlessly.
  • Express.js 4.21: Fast, unopinionated minimalist web framework providing RESTful API endpoints, request parsing, and error-handling middleware.
  • JSON Web Tokens (JWT) & bcryptjs: Stateless authentication mechanism generating tamper-evident signed HS256 tokens and salted password hashing (salt work factor: 12).
  • Node.js Native Crypto Module: Generates cryptographically strong pseudorandom bytes (crypto.randomBytes(32)) and SHA-256 token digests.
  • express-rate-limit: Enforces IP-based rate limiting on sensitive authentication and ticket scanning routes to prevent brute-force attacks.

Database Technology

  • MongoDB & Mongoose ODM 8.9: Document database utilizing the WiredTiger storage engine configured as a Replica Set to enable multi-document ACID transactions. Mongoose provides robust schema validation and indexing.

Methodology

The engineering of CampusPass followed a rigorous Hybrid Prototype-Waterfall Lifecycle. This hybrid paradigm combined rapid iterative prototyping for user-facing components with disciplined, structured verification for concurrency-critical transaction logic.

Development Phases

  • Phase 1: Requirement Analysis & Threat Modeling: Defined user personas, evaluated auditorium entry workflows, and identified potential security exploits such as duplicate scans, race condition overbooking, and QR tampering.
  • Phase 2: Database & Concurrency Architecture: Formulated Mongoose models with strict compound indexes (e.g. { eventId: 1, email: 1 }) and designed ACID transaction flows with retry loops.
  • Phase 3: Backend RESTful API Implementation: Developed Express routes for JWT organizer authentication, event CRUD, transactional seat reservation, and atomic check-ins.
  • Phase 4: Client-Side SPA Engineering: Built modular React components for event listings, student registration, dynamic pass generation, camera scanning, and organizer dashboards.
  • Phase 5: Automated Testing & Stress Validation: Executed end-to-end integration tests verifying concurrent registrations, capacity limits, duplicate admission handling, and CSV attendance export.

Engineering Advantages of This Methodology

  • Early Risk Mitigation: Prototyping camera scanning and canvas rendering early highlighted browser permission and scaling constraints, allowing timely adjustments.
  • Strict Concurrency Guarantees: Treating seat counts and ticket issuance as atomic database operations eliminated race conditions at the architectural level.
  • Zero-Trust Security Design: Hashing QR tokens in the database ensures that even an internal database administrator or compromised dump cannot be used to forge valid event passes.

Database Structure

CampusPass utilizes a highly optimized document schema hosted on a MongoDB WiredTiger replica set. Relationships are preserved via ObjectId references with unique compound indexes.

Indexing Strategy

  • organizers.email: Unique ascending index preventing duplicate administrative registrations.
  • tickets.ticketCode: Unique index enabling sub-millisecond lookup for manual check-ins.
  • tickets.qrTokenHash: Unique index enabling instantaneous SHA-256 cryptographic token lookups.
  • tickets.{ eventId: 1, email: 1 }: Unique compound index strictly restricting one registration per student email address per event.

Coding - Backend

The Express.js backend handles cryptographic generation, concurrency control, and atomic verification. The following production excerpts showcase the core algorithmic implementations.

1. Concurrency Control with MongoDB Transactions (server.js)

server.js — Transactional Seat Reservation
const session = await mongoose.startSession();
try {
  await session.withTransaction(async () => {
    // Atomically reserve seat only if bookedSeats is strictly less than maxSeats
    event = await Event.findOneAndUpdate(
      { _id: eventId, $expr: { $lt: ["$bookedSeats", "$maxSeats"] } },
      { $inc: { bookedSeats: 1 } },
      { new: true, session }
    );
    if (!event) {
      const exists = await Event.exists({ _id: eventId }).session(session);
      const err = new Error(exists ? "This event is sold out." : "Event not found.");
      err.status = exists ? 409 : 404; throw err;
    }
    // Create ticket document inside the same isolated transaction
    await Ticket.create([{ eventId, studentName, email, collegeId, ticketCode, qrTokenHash: hash(token) }], { session });
  });
} finally { await session.endSession(); }

2. Atomic Check-In & Anti-Duplicate Verification (server.js)

server.js — Atomic Pass Verification
const lookup = token ? { qrTokenHash: hash(token) } : { ticketCode: code };
const checkedInAt = new Date();

// Atomic query: updates only if isCheckedIn is currently false
const ticket = await Ticket.findOneAndUpdate(
  { ...lookup, eventId: event._id, isCheckedIn: false },
  { $set: { isCheckedIn: true, checkedInAt } },
  { new: true }
);
if (ticket) return res.json({ status: "success", message: "Check-in successful!", studentName: ticket.studentName, checkedInAt });

// If no document updated, determine precise failure reason
const found = await Ticket.findOne(lookup).select("eventId isCheckedIn checkedInAt").lean();
if (!found) return res.status(404).json({ status: "invalid", message: "Invalid ticket." });
if (String(found.eventId) !== String(event._id)) return res.status(400).json({ message: "Wrong event pass." });
return res.status(409).json({ status: "already_used", message: "Ticket already used.", checkedInAt: found.checkedInAt });

2. Real-Time HTML5 Camera Scanner Component (App.jsx)

App.jsx — WebRTC Camera Scanner Lifecycle
function Scanner({ onScan }) {
  const [active, setActive] = useState(false);
  useEffect(() => {
    if (!active) return;
    const scanner = new Html5Qrcode("qr-reader");
    // Start camera video stream with environment (back) camera preference
    scanner.start(
      { facingMode: "environment" },
      { fps: 10, qrbox: { width: 220, height: 220 } },
      decoded => {
        setActive(false);
        onScan(decoded); // Dispatch decoded token to checkIn handler
      }
    ).catch(() => setActive(false));
    return () => { scanner.stop().catch(() => {}); };
  }, [active]);
  return <div><div id="qr-reader"/><button onClick={() => setActive(!active)}>{active ? "Stop" : "Scan"}</button></div>;
}

Conclusion and Future Scope

The CampusPass: Event Ticketing and QR Code Check-In System demonstrates how modern full-stack web technologies and distributed transaction principles can solve tangible operational bottlenecks in educational institutions. The platform successfully bridges student registration with gate admission control into a unified, tamper-resistant, and paperless workflow.

By implementing MongoDB ACID multi-document transactions, the system guarantees zero overbooking even during high-traffic surges. Furthermore, the decoupling of the high-entropy raw QR token from its database SHA-256 hash ensures robust cryptographic protection against pass spoofing and screenshot abuse, while atomic query locks definitively eliminate duplicate gate entries.

Future Scope & Enhancements

  • Automated Transactional Dispatch: Integrating NodeMailer / SendGrid to deliver dynamic PDF passes and ICS calendar invites directly to the student's registered college email address.
  • Native Digital Wallet Integration: Generating signed Apple Wallet (.pkpass) and Google Wallet passes for NFC and lock-screen barcode access.
  • WebSocket Real-Time Multi-Gate Synchronization: Utilizing Socket.io to synchronize check-in counts in real time across multiple concurrent gatekeepers at large auditorium entrances.
  • Offline-First Gatekeeper Progressive Web App (PWA): Implementing Service Workers and local SQLite / IndexedDB encryption to allow gate check-ins during campus network outages with background reconciliation.
  • Facial Recognition Verification: Optional integration of computer vision biometric verification comparing attendee webcam captures against student identity card records.
